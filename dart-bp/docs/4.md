# Settlement

A settlement can have 1 or more **Leg**s as each Leg represents one asset transfer. Say Alice wants to send 10 units of asset id $at$ to Bob, then such a settlement will have 1 leg with Alice as sender and Bob as receiver.
If Alice wants to swap asset 10 units of $at$ with Bob for 20 units of $at'$, then such a settlement will have 2 legs with Alice acting as sender in one leg and receiver in other and vice versa for Bob.

Settlements might be created by sender, receiver or a third party. To keep the amount, and identities of parties confidential, the settlement creator encrypts these details including asset-id so that the chain does not even learn which asset is being traded. However, the chain knows how many legs the settlement has. The encryption is done for all parties to that leg which include sender, receiver and all auditors and mediators for that asset.
Following describes the creation of a leg, its encryption, decryption and the proof that the leg is correctly generated.

There are some options a creator has: It can choose to reveal the asset-id to the verifier (chain) making the proofs if the use-case permits, much proofs more efficient. 
It can also decide if sender and receiver learn each other's public key. Finally, it can choose to include additional auditors and mediators than already associated with the asset 
but these auditors and mediators keys become public and not hidden like the auditors and mediators keys associated with the asset. 

Note: Following is the proof for 1 leg only. A settlement is a collection of legs and thus collection of following proofs except the curve tree membership proof is batched.


## Leg

A leg has:

1. $EK_s$ - Encryption public key of sender
2. $EK_r$ - Encryption public key of receiver
3. $v$ - Amount of units being transferred
4. $at$ - Asset-id being transferred
5. $enc\_keys$ - List of encryption keys $EK_i$ stored with the asset (hidden from verifier unless asset-id is revealed). These keys belong to auditors and mediators who share encryption keys.
6. $med\_keys$ - List of pairs $(idx, MK)$ where $idx$ is the index in $enc\_keys$ and $MK$ is the mediator's affirmation public key (hidden from verifier unless asset-id is revealed)
7. $public\_enc\_keys$ - List of encryption keys provided by leg creator (always revealed to verifier). These act as additional auditors beyond those associated with the asset.

### Encryption
The settlement creator wants to ensure that the same leg encryption is given to all parties and thus uses twisted Elgamal.

Note that an encryption key can be shared between an auditor and a mediator (see system model in 1.md). The issuer distributes the corresponding encryption secret key using key-distribution-proof to all such parties before they start auditing/mediating. The $Eph_{e_i}$ in the leg is for a single $EK_i$, so if a mediator shares the same $EK$ as an auditor at index $idx$, they use $Eph_{e_{idx}}$ to decrypt.

**Configuration flags.** Two booleans control what's included in the encryption:

- `parties_see_each_other`: if true, the sender's ephemeral key carries an extra $EK_s.r_2$ component (so the sender can decrypt the receiver's $EK_r$ from $CT_r$) and the receiver's carries an extra $EK_r.r_1$ component (so the receiver can decrypt $EK_s$ from $CT_s$). If false, these are absent and the two parties cannot learn other's identity.
- `sender_receiver_decryption_needed` (derived): this is `parties_see_each_other` OR (the asset has any encryption keys, i.e. there's at least one auditor/mediator sharing an encryption key with the asset). When true, the ratios $r_2/r_1$ and $r_1/r_2$ must appear as witnesses in the Bulletproof commitment (see "Leg creation proof" below). The reason it can be true even when parties don't see each other is that auditor ephemeral keys still need the $r_2$ component proven correct relative to $r_1$ — specifically the proof $Eph_{e_i}[1] = Eph_{e_i}[0] \cdot (r_2/r_1)$ requires the ratio as a witness.

1. Creator picks 3 (or 4) independent random scalars $r_1, r_2, r_3 \in \mathbb{Z}_p$ (and optionally $r_4 \in \mathbb{Z}_p$ if asset-id is encrypted) and creates ciphertexts:
   $$CT_s = r_1.G_{Enc} + EK_s$$
   $$CT_r = r_2.G_{Enc} + EK_r$$
   $$CT_v = r_3.G_{Enc} + v.H$$
   $$CT_{at} = r_4.G_{Enc} + at.H \quad \text{(only if asset-id is not revealed)}$$

   These follow the twisted Elgamal pattern with the same ephemeral randomness $r_i$ shared across all parties. 

2. For each asset encryption key $EK_i$ (auditors, and mediators sharing a key), create ephemeral keys to allow them to decrypt $CT_s, CT_r, CT_v$ (and optionally $CT_{at}$ if asset-id is encrypted):
   $$Eph_{e_i} = (EK_i.r_1, EK_i.r_2, EK_i.r_3, EK_i.r_4)$$
   Each auditor/mediator who holds $ek_i$ can compute $ek_i^{-1}.Eph_{e_i}[j] = r_j.G_{Enc}$ and subtract it from the corresponding $CT$ to decrypt.

3. Similarly, sender and receiver each get their own ephemeral keys:
   - Sender gets: $Eph_s = (EK_s.r_1, EK_s.r_3, EK_s.r_4)$ ($EK_s.r_2$ is optionally included if senders and receivers are allowed to learn each other)
   - Receiver gets: $Eph_r = (EK_r.r_2, EK_r.r_3, EK_r.r_4)$ ($EK_r.r_1$ is optionally included if senders and receivers are allowed to learn each other)

4. For each mediator affirmation key $MK_j$ (at enc-key index $idx_j$), creator picks a fresh independent random $r_{m_j} \in \mathbb{Z}_p$ and creates:
   $$CT_{m_j} = r_{m_j}.G_{Enc} + MK_j$$
   $$Eph_{m_j} = EK_{idx_j}.r_{m_j}$$
   This allows the mediator (who holds $ek_{idx_j}^{-1}$) to recover $r_{m_j}.G_{Enc}$ and learn $MK_j$.

5. For public encryption keys (auditors who don't need encrypted randomness), create ephemeral keys directly:
   $$Eph_{public\_e_i} = (PK_i.r_1, PK_i.r_2, PK_i.r_3, PK_i.r_4)$$
   where $PK_i$ is the i-th public encryption key (the $r_4$ component is omitted when asset-id is revealed). The public auditor recovers $r_j.G_{Enc} = (PK_i.r_j) \cdot ek_i^{-1}$ using its secret key.

The full leg encryption is:
$$
(CT_s, CT_r, CT_v, CT_{at}, Eph_s, Eph_r, [Eph_{e_0}, Eph_{e_1}, ...], [CT_{m_0}, Eph_{m_0}, CT_{m_1}, Eph_{m_1}, ...],$$
$$[Eph_{public\_e_0}, Eph_{public\_e_1}, ...])
$$

### Decryption
Sender/receiver knows their encryption key pair $(ek, EK)$. The leg encryption itself doesn't tell a recipient whether they are the sender or the receiver — unless the leg creator informs them out of band, they have to try both roles and the one that recovers their own $EK$ is the correct one.

**As sender** (try first):
1. Recover $r_1.G_{Enc} = ek_s^{-1}.Eph_s[0]$ (since $ek_s^{-1}.(EK_s.r_1) = r_1.G_{Enc}$), then check $CT_s - r_1.G_{Enc} = EK_s$. If equality holds, the recipient is the sender of this leg; otherwise they are not.
2. Recover $r_3.G_{Enc} = ek_s^{-1}.Eph_s[2]$ and $r_4.G_{Enc} = ek_s^{-1}.Eph_s[3]$ (when asset-id is hidden), then decrypt amount and asset-id by solving discrete log in:
   $$v.H = CT_v - r_3.G_{Enc}$$
   $$at.H = CT_{at} - r_4.G_{Enc}$$
   Since $v$ and $at$ are small (48-bit and 32-bit respectively), discrete log is feasible in reasonable time.

**As receiver** (if sender check failed): repeat the same steps with $Eph_r[1]$ instead of $Eph_s[0]$ to recover $r_2.G_{Enc}$ and check $CT_r - r_2.G_{Enc} = EK_r$; if yes the recipient is the receiver. Amount/asset-id decryption then uses $Eph_r[2]$ and $Eph_r[3]$ in place of $Eph_s[2]$, $Eph_s[3]$.

For auditors/mediators with encryption key pair $(ek_i, EK_i)$:

1. Decrypt $CT_{at}$ first (when asset-id is hidden) to check whether this leg is for an asset they care about — i.e. whether the recovered $at$ matches an asset for which they are an auditor/mediator. This acts as a filter: if the asset doesn't match, they skip the rest. 
2. If the asset matches, decrypt $CT_s, CT_r, CT_v$ in the same way: compute $r_j.G_{Enc} = ek_i^{-1}.Eph_{e_i}[j]$ for $j \in \{1, 2, 3\}$ and subtract from the corresponding ciphertext.
3. If mediator, additionally recover affirmation key: $r_{m_j}.G_{Enc} = ek_i^{-1}.Eph_{m_j}$, then $MK_j = CT_{m_j} - r_{m_j}.G_{Enc}$.

## Leg creation proof
The proof for leg creation needs to hide:

- The sender and receiver's public key
- The amount being transferred
- The asset being transacted. This is the most complicated part as it needs to prove that all the transaction details are being 
  encrypted for the asset's auditors and mediators without revealing the asset or identity of auditors and mediators. This can be made 
  optional by leg creator however for efficiency.

**Key complexity when asset-id is hidden.** Here the asset's auditor encryption keys $EK_i$ and mediator affirmation keys $MK_j$ must also be kept hidden from the verifier — revealing them would identify the asset. The proof therefore works over re-randomized versions $E_i$ and $M_j$ (derived from the asset leaf via the Pedersen-commitment-to-curve-points machinery described below) and proves each leg ephemeral key was built from the corresponding hidden key without exposing it. This is the source of most of the steps 5–11: each asset leaf point is re-randomized as $E_i = EK_i + bl_i.B_{blinding}$ and $M_j = J_0 + J_1.idx_j + MK_j + bl_{n+j}.B_{blinding}$. When asset-id is revealed the asset's keys $EK_i, MK_j$ are public inputs. The asset's public encryption keys ($public\_enc\_keys$) are always revealed regardless, since they were specified directly by the leg creator and are not part of the asset leaf.

Recall from the "System model" section that an asset's data is stored in a leaf of the asset curve tree. The leaf now uses two generators $J_0, J_1 \in \mathbb{G}_p$ to distinguish auditor encryption keys from mediator combined keys:
$$
Leaf_{asset\_id} = (P_0.x).\widetilde{G}_0 + (P_1.x).\widetilde{G}_1 + ... + (P_{n+m}.x).\widetilde{G}_{n+m}, \quad Leaf_{asset\_id} \in \mathbb{G}_q
$$
where points are constructed as:
- $P_0 = asset\_id.J_0$
- For each auditor $i$: $P_i = EK_i$
- For each mediator $j$ with enc key index $idx_j$: $P_{n+j} = J_0 + J_1.idx_j + MK_j$

Here $MK_j$ is the mediator's affirmation public key. The $J_1.idx_j$ encodes which auditor encryption key belongs to mediator $j$ (since mediators also have an encryption key they share with auditors, at position $idx_j$ in the auditor key list).

Now this pushes $Leaf_{asset\_id}$ in a different group $\mathbb{G}_q$ (Vesta curve) whereas all public keys are in $\mathbb{G}_p$ (Pallas curve). We use a similar technique used by Curve tree paper. The key idea is that the asset-id and encryption keys for all auditors and mediators is committed in a single Pedersen commitment where the x-coordinate of the item "represents" the item and then we randomize each item and can treat as a group element which can be revealed. Since the $asset\_id \in \mathbb{Z}_p$, we shift it to $\mathbb{G}_p$ by multiplying it by a public $J_0 \in \mathbb{G}_p$. Following describes the general protocol

**Pedersen Commitment to Curve Points**

Commits to elliptic curve points by committing to their x-coordinate the same way curve trees do. Then the knowledge of those committed points can be proven along with generating a re-randomized version of each point.
Given points $P_i \in \mathbb{G}_p$ as 

$$A = [P_0, P_1, ..., P_n]$$ 

Commit to $A$ in a Pedersen commitment of x-coordinate of each $P_i$, i.e. 

$$P_i.x \in C = PedCom(P_0.x, P_1.x, ..., P_n.x) = \sum_{\widetilde{G}_i.P_i.x}$$ 

where $C \in \mathbb{G}_q$ and $P_i.x \in \mathbb{Z}_q$ where $\mathbb{G}_p, \mathbb{G}_q$ are on 2 curves which form a 2-cycle (base field of one equals scalar field of other).

1. Prover randomizes each $P_i$ to get 
  $$A_r = [{P_r}_0, {P_r}_1, ..., {P_r}_n]$$
  
  where 
  
  $$A_r[i] = P_{r_i} = P_i + bl_i.B_{blinding}$$ 

  $$B_{blinding} \in \mathbb{G}_p, \quad bl_i \stackrel{\$}{\leftarrow} \mathbb{Z}_p$$.

2. Prover proves $\forall i, P_i \in \mathbb{G}_p$, i.e. $P_i.x, P_i.y$ are x and y coordinates of a point which lies in group $\mathbb{G}_p$ and $P_i.x, P_i.y \in \mathbb{Z}_q$.
3. Prover proves $\forall i, A_r[i] = A[i] + bl_i.B_{blinding} = P_i + bl_i.B_{blinding}$
4. For a chosen subset $S$ of the indices, the prover additionally outputs, for each $i \in S$, the same blinding $bl_i$ committed under a **different** generator $B \in \mathbb{G}_p$ (with $B \neq B_{blinding}$):
  $$bl_i.B$$
  and proves (a shared-scalar discrete-log relation in the same circuit) that this $bl_i$ is the *same* scalar used in $A_r[i] = P_i + bl_i.B_{blinding}$. The values $\{bl_i.B\}_{i \in S}$ are public. They let a caller bind some *other* witness to the re-randomization blinding $bl_i$ — by checking that witness against $bl_i.B$ — without revealing $bl_i$. The leg creation proof uses this to pin the Bulletproof blinding witnesses $l_i$ / $k_j$ to the actual re-randomization blindings (see steps 6, 11 below).

The implementation adds a public element $\Delta$ to each $P_i$ as mentioned in the curve tree paper.

In our usage of the above protocol, $A$ corresponds to the points making up the asset leaf:
- $A[0] = asset\_id.J_0$
- $A[i] = EK_i$ for each of the $n$ auditor encryption keys
- $A[n+j] = J_0 + J_1.idx_j + MK_j$ for each of the $m$ mediators

The subset $S = \{1, \dots, n+m\}$ — i.e. every auditor and mediator point also gets the second commitment $bl_i.B$. The asset-id point at index $0$ is excluded since its blinding $bl_0$ is proven directly in $T_{AT_r}$ (step 8).

**Notation.** The blindings used to re-randomize the asset leaf points are written $bl_0, bl_1, \dots, bl_{n+m}$ throughout (so $bl_0$ is the asset-id blinding, $bl_1, \dots, bl_n$ are the encryption-key blindings, and $bl_{n+1}, \dots, bl_{n+m}$ are the mediator-key blindings, matching $A$'s indexing above). In the Bulletproof commitment (step 9 below) the encryption-key blindings appear as the witnesses $l_i := bl_{i+1}$ for $i = 0, \dots, n-1$ (the offset is because $bl_0$ is for the asset-id and is handled separately in $T_{AT_r}$), and the mediator-key blindings appear as $k_j := bl_{n+j+1}$ for $j = 0, \dots, m-1$ (not committed in the BP — they are only used in $T_{CT_{m_j}}$). The mediator encryption randomnesses from the leg encryption are written $m_j := r_{m_j}$ when they appear as BP witnesses. For any witness $x$ used in a Schnorr T-value, we write its random blinding as $x_r$ (e.g. $r_{1_r}$ is the Schnorr blinding for $r_1$); when $x$ itself is a compound expression we write the blinding as $(x)_r$ for clarity (e.g. $(bl_i \cdot r_1)_r$).

A prover (settlement creator) wants to prove following relations when creating a leg with amount $v$:

1. $CT_v, CT_{at}$ correctly encrypt the amount and asset-id (and similarly $CT_s, CT_r$ encrypt $EK_s, EK_r$).
2. For each auditor with index $i$, each component of $Eph_{e_i}$ matches the corresponding leg randomness paired with the i-th auditor's encryption key in the asset leaf: $Eph_{e_i}[0] = r_1.EK_i$, $Eph_{e_i}[1] = r_2.EK_i$, $Eph_{e_i}[2] = r_3.EK_i$, $Eph_{e_i}[3] = r_4.EK_i$ (the last component is present only when asset-id is hidden). For each mediator $j$ with enc-key index $idx_j$, $Eph_{m_j} = r_{m_j}.EK_{idx_j}$ (using the asset auditor's encryption key at index $idx_j$). The same enforcement applies to $Eph_s, Eph_r$ against $EK_s, EK_r$. This also involves a curve tree membership proof so the verifier knows $EK_i, MK_j$ come from a legitimate asset leaf without revealing which asset.
3. The Bulletproof blinding witness $l_i$ used in the $Eph_{e_i}[0]$ relation equals the actual re-randomization blinding $bl_i$ of $E_i$, and the mediator witness $k_j$ used in the $CT_{m_j}$ relation equals $bl_{n+j}$ of $M_j$. This is the binding that makes relation 2 sound when $EK_i$/$MK_j$ are hidden: $Eph_{e_i}[0] = r_1.(E_i - l_i.B_{blinding})$, and without forcing $l_i = bl_i$ a malicious creator could pick $l_i \neq bl_i$ to get $Eph_{e_i}[0] = r_1.EK_i + r_1.(bl_i - l_i).B_{blinding} \neq r_1.EK_i$ — the proof would still verify but auditor $i$ (resp. mediator $j$) would be unable to decrypt. The binding is proven against the public $bl_i.B$ / $bl_{n+j}.B$ from the Pedersen-commitment-to-curve-points protocol above.
4. $v <= MAX\_BALANCE$


**Instance**: $CT_s$, $CT_r$, $CT_v$, $CT_{at}$, $Eph_s$, $Eph_r$, $[Eph_{e_i}]$, $[CT_{m_i}]$, $[Eph_{m_i}]$, $[Eph_{public\_e_i}]$, $A_r = [AT_r, E_1, ..., E_n, M_1, ..., M_m]$ (re-randomized points), $[bl_1.B, ..., bl_{n+m}.B]$ (blindings under the second generator), $Path_r$, $Root$, $G_{Enc}$, $H$, $J_0$, $J_1$, $B_{blinding}$, $B$, curve tree generators

**Witness**: $v, at, r_1, r_2, r_3, r_4, r_1^{-1}, r_2^{-1}, EK_s, EK_r, EK_i, MK_j, [r_{m_j}], [bl_i], Path$.

Above are the high level instance and witness values known before the protocol starts and don't include instance and witness created during protocol execution like the various blindings and $T$ values.


### Prover
1. Prover creates list of points for asset-id and keys as $$A = [at.J_0, EK_1, EK_2, ... EK_n, J_0 + J_1.idx_1 + MK_1, ..., J_0 + J_1.idx_m + MK_m]$$
   where $EK_i$ are auditor encryption keys and $MK_j$ are mediator affirmation keys with their enc key index $idx_j$.
2. Create blindings $blindings = [bl_0, bl_1, ..., bl_{n+m}]$ and randomize $A$ as $$A_r = [AT_r, E_1, ..., E_n, M_1, ..., M_m]$$
   where $AT_r = at.J_0 + bl_0.B_{blinding}$, $E_i = EK_i + bl_i.B_{blinding}$, and $M_j = J_0 + J_1.idx_j + MK_j + bl_{n+j}.B_{blinding}$. $A_r$ is shared with the verifier.
3. Take coordinates of all points in
   - $A_r$ as $$x_r=[(AT_r + \Delta).x, (E_1 + \Delta).x, ..., (E_n + \Delta).x, (M_1 + \Delta).x, ..., (M_m + \Delta).x]$$ and similar for $y_r$
   - $A$ as $$x=[(at.J_0 + \Delta).x, (EK_1 + \Delta).x, ..., (EK_n + \Delta).x, (J_0 + J_1.idx_0 + MK_1 + \Delta).x, ..., (J_0 + J_1.idx_m + MK_m + \Delta).x]$$ and similar for $y$
4. Enforces constraints that for each $i$:
   - $(x_i, y_i)$ is a valid curve point
   - $(x_i, y_i) + bl_i.B_{blinding} = (x_{r_i}, y_{r_i})$. The RHS is public but the LHS only has public the fixed point ($B_{blinding}$) .
5. Since each re-randomized enc-key is $E_i = EK_i + bl_i.B_{blinding}$, the prover can substitute $EK_i = E_i - bl_i.B_{blinding}$. For each of the $n$ auditor encryption keys, the ephemeral key relation is $Eph_{e_i}[0] = r_1.EK_i = r_1.(E_i - bl_i.B_{blinding})$.
6. Write $Eph_{e_i}[0] = r_1.E_i + (r_1.bl_i).(-B_{blinding})$. This is a 2-witness Pedersen commitment with witnesses $(r_1, r_1.bl_i)$ and bases $(E_i, -B_{blinding})$. The product $r_1.bl_i$ is enforced by a Bulletproof multiplication constraint. The remaining ephemeral key entries use ratios: $Eph_{e_i}[1] = (r_2/r_1).Eph_{e_i}[0]$, $Eph_{e_i}[2] = (r_3/r_1).Eph_{e_i}[0]$, $Eph_{e_i}[3] = (r_4/r_1).Eph_{e_i}[0]$.
7. For proving $CT_s = r_1.G_{Enc} + r_1^{-1}.Eph_s[0]$ (where $Eph_s[0] = EK_s.r_1$), prover uses witnesses $(r_1, r_1^{-1})$ with bases $(G_{Enc}, Eph_s[0])$. Similarly for $CT_r = r_2.G_{Enc} + r_2^{-1}.Eph_r[1]$ using $(r_2, r_2^{-1})$. The constraints $r_1 \cdot r_1^{-1} = 1$ and $r_2 \cdot r_2^{-1} = 1$ are enforced in Bulletproofs.
8. For proving $AT_r = at.J_0 + bl_0.B_{blinding}$, prover picks random $at_r, bl_{0_r} \in \mathbb{Z}_p$ and creates:
   $$T_{AT_r} = at_r.J_0 + bl_{0_r}.B_{blinding}, \in \mathbb{G}_p$$
9. For the unified Bulletproof commitment, prover commits to the witness array:
   $$witnesses = [v, r_1, r_2, r_3, r_4, r_1^{-1}, r_2^{-1}, r_3/r_1, r_3/r_2, r_4/r_1, r_4/r_2, (r_2/r_1)^*, (r_1/r_2)^*, l_0, l_0 \cdot r_1, ..., l_{n-1}, l_{n-1} \cdot r_1, m_0, m_0 / r_1, ..., m_{m-1}, m_{m-1} / r_1]$$
   where $(r_2/r_1)^*$ and $(r_1/r_2)^*$ are only present if `sender_receiver_decryption_needed` is true. The commitment to $witnesses$ is:
   $$C_{BP} = b.B_{blinding} + v.G_1 + r_1.G_2 + r_2.G_3 + ... \in \mathbb{G}_p$$
   where $b$ is a fresh random blinding and $G_i$ are Bulletproof generators.
10. Bulletproof constraints enforce:
    - $r_1 \cdot r_1^{-1} = 1$ and $r_2 \cdot r_2^{-1} = 1$
    - $r_1 \cdot (r_3/r_1) = r_3$ and $r_2 \cdot (r_3/r_2) = r_3$
    - $r_1 \cdot (r_4/r_1) = r_4$ and $r_2 \cdot (r_4/r_2) = r_4$
    - If `sender_receiver_decryption_needed`: $r_1 \cdot (r_2/r_1) = r_2$ and $r_2 \cdot (r_1/r_2) = r_1$
    - For each encryption key: $r_1 \cdot l_i = l_i \cdot r_1$
    - For each mediator: $r_1 \cdot (m_i / r_1) = m_i$
    - $v \leq MAX\_BALANCE$ (range proof)
11. **Sender/receiver ciphertext proofs**: Prover picks random $r_{1_r}, r_{1^{-1}_r}, r_{2_r}, r_{2^{-1}_r} \in \mathbb{Z}_p$ and creates:
    $$T_{CT_s} = r_{1_r}.G_{Enc} + r_{1^{-1}_r}.Eph_s[0] \in \mathbb{G}_p$$
    $$T_{CT_r} = r_{2_r}.G_{Enc} + r_{2^{-1}_r}.Eph_r[1] \in \mathbb{G}_p$$

    **Auditor enc-key ephemeral proofs**: For each of the $n$ auditor enc_keys (with $bl_i$ denoting the blinding of the $i$-th re-randomized enc-key entry $E_i = EK_i + bl_i.B_{blinding}$ — the same $bl_i$ appears as the witness $l_i$ in the Bulletproof commitment of step 9), prover proves $Eph_{e_i}[0] = r_1.E_i + (r_1.bl_i).(-B_{blinding})$. Reusing $r_{1_r}$ from the sender ciphertext proof above (so the $r_1$ response is shared) and picking a fresh blinding $(bl_i \cdot r_1)_r \in \mathbb{Z}_p$ for the product witness $bl_i \cdot r_1$, prover creates:
    $$T_{Eph_{e_i}[0]} = r_{1_r}.E_i + (bl_i \cdot r_1)_r.(-B_{blinding}) \in \mathbb{G}_p$$

    **Auditor blinding binding**: The relation above only gives $Eph_{e_i}[0] = r_1.EK_i$ if the committed $l_i$ equals the true re-randomization blinding $bl_i$. To enforce that, the prover proves $l_i.B = bl_i.B$ against the public $bl_i.B$ (whose $bl_i$ the curve-tree proof already ties to $E_i$). It reuses the Bulletproof commitment's Schnorr blinding $l_{i_r}$ for the $l_i$ witness — so the $l_i$ response is shared from $resp_{C_{BP}}$ and there is no separate stored response — and creates:
    $$T_{bl_i} = l_{i_r}.B \in \mathbb{G}_p$$

    **Mediator ciphertext and ephemeral proofs**: For each of the $m$ mediator entries in the asset leaf (with re-randomized entry $M_j = J_0 + J_1.idx_j + MK_j + bl_{n+j}.B_{blinding}$), prover proves:
    - $CT_{m_j}$ is correctly encrypted: let $D_j = CT_{m_j} + J_0 + J_1.idx_j - M_j$ (computable from public values). The prover knows witnesses $(r_{m_j}, bl_{n+j})$ in $D_j = r_{m_j}.G_{Enc} + bl_{n+j}.(-B_{blinding})$. Prover picks random $r_{m_{j,r}}, bl_{(n+j),r} \in \mathbb{Z}_p$ and creates: $$T_{CT_{m_j}} = r_{m_{j,r}}.G_{Enc} + bl_{(n+j),r}.(-B_{blinding}) \in \mathbb{G}_p$$
    - $bl_{n+j}$ is bound to the leaf re-randomization: the prover proves the $bl_{n+j}$ witness used in $D_j$ above equals the actual re-randomization blinding of $M_j$, against the public $bl_{n+j}.B$. Reusing the $CT_{m_j}$ proof's Schnorr blinding $bl_{(n+j),r}$ (so the response is shared from $resp_{CT_{m_j}}[1]$), prover creates: $$T_{k_j} = bl_{(n+j),r}.B \in \mathbb{G}_p$$ Without this, a malformed $CT_{m_j}$ (offset by a multiple of $B_{blinding}$) would still verify but the mediator would recover a wrong $MK_j$.
    - $Eph_{m_j}$ is correctly formed: $Eph_{m_j} = r_{m_j}.EK_{idx_j}$. Since $EK_{idx_j} \cdot r_1 = Eph_{e_{idx_j}}[0]$ (the $r_1$ ephemeral key for that auditor, already a public part of the leg encryption), this is equivalent to
      $$Eph_{m_j} = Eph_{e_{idx_j}}[0] \cdot (r_{m_j}/r_1)$$
      Prover proves this as a single-witness discrete log with witness $m_j/r_1$ (which is committed in the Bulletproof commitment as $m_j/r_1$, where $m_j = r_{m_j}$) and base $Eph_{e_{idx_j}}[0]$. Picking a fresh blinding $(m_j/r_1)_r \in \mathbb{Z}_p$:
      $$T_{Eph_{m_j}} = (m_j/r_1)_r.Eph_{e_{idx_j}}[0] \in \mathbb{G}_p$$
      The Bulletproof multiplication constraint $r_1 \cdot (m_j/r_1) = m_j$ binds the $m_j$ used in $CT_{m_j}$ above to the $m_j/r_1$ used here.

    **Public encryption key proofs**: For each public encryption key $PK_i$, prover proves the four ephemeral key entries $Eph_{public\_e_i}[0] = PK_i.r_1$, $Eph_{public\_e_i}[1] = PK_i.r_2$, $Eph_{public\_e_i}[2] = PK_i.r_3$, $Eph_{public\_e_i}[3] = PK_i.r_4$ by reusing $r_{1_r}, r_{2_r}, r_{3_r}, r_{4_r}$ from the sender/receiver/amount/asset-id ciphertext proofs above:
    $$T_{Eph_{public\_e_i}[0]} = r_{1_r}.PK_i,  \quad T_{Eph_{public\_e_i}[1]} = r_{2_r}.PK_i,  \quad T_{Eph_{public\_e_i}[2]} = r_{3_r}.PK_i,  \quad T_{Eph_{public\_e_i}[3]} = r_{4_r}.PK_i$$
12. For $Eph_{e_i}[1]$, prover picks random $(r_2/r_1)_r \in \mathbb{Z}_p$ and creates:
    $$T_{Eph_{e_i}[1]} = (r_2/r_1)_r.Eph_{e_i}[0] \in \mathbb{G}_p$$
13. For $Eph_{e_i}[2]$, prover picks random $(r_3/r_1)_r \in \mathbb{Z}_p$ and creates:
    $$T_{Eph_{e_i}[2]} = (r_3/r_1)_r.Eph_{e_i}[0] \in \mathbb{G}_p$$
14. For $Eph_{e_i}[3]$, prover picks random $(r_4/r_1)_r \in \mathbb{Z}_p$ and creates:
    $$T_{Eph_{e_i}[3]} = (r_4/r_1)_r.Eph_{e_i}[0] \in \mathbb{G}_p$$
15. For the Bulletproof commitment $C_{BP}$, prover picks random blindings for each witness and creates:
     $$T_{C_{BP}} = b_r.B_{blinding} + v_r.G_1 + r_{1_r}.G_2 + r_{2_r}.G_3 + r_{3_r}.G_4 + r_{4_r}.G_5 + ... \in \mathbb{G}_p$$
     where the blindings correspond to the witness array structure from step 9.
16. For proving $CT_v = r_3.G_{Enc} + v.H$ and $CT_{at} = r_4.G_{Enc} + at.H$, prover picks random $$r_{3_r}, v_r, r_{4_r} \in \mathbb{Z}_p$$ and creates:
    $$T_{CT_v} = r_{3_r}.G_{Enc} + v_r.H \in \mathbb{G}_p$$
    $$T_{CT_{at}} = r_{4_r}.G_{Enc} + at_r.H \in \mathbb{G}_p$$
    Note: $at_r$ was already created in step 8 for the asset-id commitment $T_{AT_r}$.
17. Prover hashes the following to create challenge $c$ as:
    $$c = Hash(A_r, Path_r, Root, Leg\_Enc, C_{BP}, T_{AT_r}, T_{CT_s}, T_{CT_r},$$
    $$T_{Eph_{e_i}[0]}, T_{bl_i}, T_{Eph_{e_i}[1]}, T_{Eph_{e_i}[2]}, T_{Eph_{e_i}[3]}, $$
    $$T_{CT_{m_j}}, T_{k_j}, T_{Eph_{m_j}}, T_{Eph_{public\_e_i}[j]},$$
    $$T_{C_{BP}}, T_{CT_v}, T_{CT_{at}})$$
    where $Leg\_Enc$ is the full leg encryption structure.
18. Prover creates responses:
    - For $AT_r$ (full Pedersen commitment proof):
      $$resp_{AT} = [at_r + at \cdot c, bl_{0_r} + bl_0 \cdot c]$$
    - For $CT_s$ (partial proof, witnesses from $C_{BP}$):
      $$resp_{CT_s} = [\perp, \perp]$$
      (witnesses $r_1, r_1^{-1}$ are at indices [2], [6] of $resp_{C_{BP}}$)
    - For $CT_r$ (partial proof, witnesses from $C_{BP}$):
      $$resp_{CT_r} = [\perp, \perp]$$
      (witnesses $r_2, r_2^{-1}$ are at indices [3], [7] of $resp_{C_{BP}}$)
    - For $CT_v$ (partial proof, witnesses from $C_{BP}$):
      $$resp_{CT_v} = [\perp, \perp]$$
      (witnesses $r_3, v$ are at indices [4], [1] of $resp_{C_{BP}}$)
    - For $CT_{at}$ (partial proof):
      $$resp_{CT_{at}} = [\perp, \perp]$$
      (witness $r_4$ is at index [5] of $resp_{C_{BP}}$, and $at$ from $resp_{AT}[0]$)
19. For each enc_key $i$, prover creates responses:
    - For $Eph_{e_i}[0]$ (partial 2-witness Pedersen proof — the response for $r_1$ is shared from $resp_{C_{BP}}[2]$):
      $$resp_{Eph_{e_i}[0]} = [\perp, (bl_i \cdot r_1)_r + (bl_i \cdot r_1) \cdot c]$$
    - For $T_{bl_i}$ (binding $l_i = bl_i$): no separate response is stored — the $l_i$ response is reused from $resp_{C_{BP}}$ (the $l_{i_r} + l_i \cdot c$ entry, at index $[14 + 2i]$). Only the commitment $T_{bl_i}$ is part of the proof.
    - For $Eph_{e_i}[1]$ (partial discrete log proof):
      $$resp_{Eph_{e_i}[1]} = (r_2/r_1)_r + (r_2/r_1) \cdot c$$
      (if `sender_receiver_decryption_needed`, witness $r_2/r_1$ is at index [12] of $resp_{C_{BP}}$)
    - For $Eph_{e_i}[2]$ (partial discrete log proof):
      $$resp_{Eph_{e_i}[2]} = (r_3/r_1)_r + (r_3/r_1) \cdot c$$
      (witness $r_3/r_1$ is at index [8] of $resp_{C_{BP}}$)
    - For $Eph_{e_i}[3]$ (partial discrete log proof):
      $$resp_{Eph_{e_i}[3]} = (r_4/r_1)_r + (r_4/r_1) \cdot c$$
      (witness $r_4/r_1$ is at index [10] of $resp_{C_{BP}}$)

    For each mediator $j$, prover creates responses:
    - For $CT_{m_j}$ (Partial2 Pedersen commitment, doesn't store T commitments):
      $$resp_{CT_{m_j}} = [r_{m_{j,r}} + r_{m_j} \cdot c, bl_{(n+j),r} + bl_{n+j} \cdot c]$$
    - For $T_{k_j}$ (binding $bl_{n+j}$): no separate response is stored — it reuses $resp_{CT_{m_j}}[1]$ (the $bl_{(n+j),r} + bl_{n+j} \cdot c$ entry). Only the commitment $T_{k_j}$ is part of the proof.
    - For $Eph_{m_j}$ (partial discrete log proof):
      $$resp_{Eph_{m_j}} = (m_j / r_1)_r + (m_j / r_1) \cdot c$$
      (witness $m_j / r_1$ is at index [14 + 2n + 2j + 1] of $resp_{C_{BP}}$)
20. For public encryption keys:
    - For each public enc key $i$ (no separate responses are stored — all four are reused from $resp_{C_{BP}}$):
      $$resp_{Eph_{public\_e_i}} = [\perp, \perp, \perp, \perp]$$
      (witnesses $r_1, r_2, r_3, r_4$ are at $resp_{C_{BP}}$ indices [2], [3], [4], [5])
21. For relation $C_{BP}$, prover creates response array:
    $$resp_{C_{BP}} = [b_r + b \cdot c, v_r + v \cdot c, r_{1_r} + r_1 \cdot c, r_{2_r} + r_2 \cdot c, r_{3_r} + r_3 \cdot c, r_{4_r} + r_4 \cdot c,$$
    $$r_{1^{-1}_r} + r_1^{-1} \cdot c, r_{2^{-1}_r} + r_2^{-1} \cdot c, (r_3/r_1)_r + (r_3/r_1) \cdot c, (r_3/r_2)_r + (r_3/r_2) \cdot c,$$
    $$(r_4/r_1)_r + (r_4/r_1) \cdot c, (r_4/r_2)_r + (r_4/r_2) \cdot c, ((r_2/r_1)_r + (r_2/r_1) \cdot c)^*, ((r_1/r_2)_r + (r_1/r_2) \cdot c)^*,$$
    $$l_{0_r} + l_0 \cdot c, (l_0 \cdot r_1)_r + (l_0 \cdot r_1) \cdot c, ..., m_{0_r} + m_0 \cdot c, (m_0 / r_1)_r + (m_0 / r_1) \cdot c, ...]$$
    where entries marked with $^*$ are only present if `sender_receiver_decryption_needed` is true. Index [0] is the blinding $b$.
22. The proof is:
    $$(r1cs\_proof, re\_randomized\_path, $$
    $$resp_{CT_s}, resp_{CT_r}, resp_{CT_v}, resp_{CT_{at}}, resp_{AT}, re\_randomized\_points, ped\_comms, $$
    $$C_{BP}, T_{C_{BP}}, resp_{C_{BP}}, $$
    $$[resp_{Eph_{e_i}[0]}, T_{bl_i}, resp_{Eph_{e_i}[1]}, resp_{Eph_{e_i}[2]}, resp_{Eph_{e_i}[3]}], $$
    $$[resp_{CT_{m_j}}, T_{k_j}, resp_{Eph_{m_j}}])$$
    where $r1cs\_proof$ contains the Bulletproof R1CS proof, $re\_randomized\_path$ is the curve tree path proof, $re\_randomized\_points$ contains the primary ($A_r$) re-randomized points together with the second-generator blindings $\{bl_i.B\}$, and $ped\_comms$ are the Pedersen commitment proofs for the curve points. The binding commitments $T_{bl_i}, T_{k_j}$ are stored, but their responses are reused ($l_i$ from $resp_{C_{BP}}$, $bl_{n+j}$ from $resp_{CT_{m_j}}[1]$). Likewise the $T_{Eph_{public\_e_i}[j]}$ values are part of the transcript but their responses are reused from $resp_{C_{BP}}$, so no separate responses are stored.

### Verifier

1. Verifier hashes the following to create challenge $c$ as:
   $$c = Hash(A_r, Path_r, Root, Leg\_Enc, C_{BP}, T_{AT_r}, T_{CT_s}, T_{CT_r},$$
   $$T_{Eph_{e_i}[0]}, T_{bl_i}, T_{Eph_{e_i}[1]}, T_{Eph_{e_i}[2]}, T_{Eph_{e_i}[3]}, $$
   $$T_{CT_{m_j}}, T_{k_j}, T_{Eph_{m_j}}, T_{Eph_{public\_e_i}[j]},$$
   $$T_{C_{BP}}, T_{CT_v}, T_{CT_{at}})$$
2. Verifier enforces the Bulletproof constraints:
   - For each $i$, $(x_i, y_i)$ satisfies the curve equation (curve point validity)
   - For each $i$, $(x_i, y_i) + bl_i.B_{blinding} = (x_{r_i}, y_{r_i})$ (randomization consistency)
   - Curve tree membership: $Path_r$ leads to $Root$
   - Multiplication constraints:
     * $r_1 \cdot r_1^{-1} = 1$ and $r_2 \cdot r_2^{-1} = 1$
     * $r_1 \cdot (r_3/r_1) = r_3$ and $r_2 \cdot (r_3/r_2) = r_3$
     * $r_1 \cdot (r_4/r_1) = r_4$ and $r_2 \cdot (r_4/r_2) = r_4$
     * If `sender_receiver_decryption_needed`: $r_1 \cdot (r_2/r_1) = r_2$ and $r_2 \cdot (r_1/r_2) = r_1$
     * For each encryption key $i$: $r_1 \cdot l_i = l_i \cdot r_1$
     * For each mediator $j$: $r_1 \cdot (m_j / r_1) = m_j$
   - Range proof: $v \leq MAX\_BALANCE$
3. Verifies asset-id commitment $AT_r$ (full Pedersen commitment proof):
   $$resp_{AT}[0].J_0 + resp_{AT}[1].B_{blinding} \stackrel{?}{=} T_{AT_r} + AT_r \cdot c$$
4. Verifies $CT_s$ using shared responses from $resp_{C_{BP}}$:
   $$resp_{C_{BP}}[2].G_{Enc} + resp_{C_{BP}}[6].Eph_s[0] \stackrel{?}{=} T_{CT_s} + CT_s \cdot c$$
   (witnesses $r_1, r_1^{-1}$ at indices [2], [6])
5. Verifies $CT_r$ using shared responses from $resp_{C_{BP}}$:
   $$resp_{C_{BP}}[3].G_{Enc} + resp_{C_{BP}}[7].Eph_r[1] \stackrel{?}{=} T_{CT_r} + CT_r \cdot c$$
   (witnesses $r_2, r_2^{-1}$ at indices [3], [7])
6. Verifies $CT_v$ using shared responses from $resp_{C_{BP}}$:
   $$resp_{C_{BP}}[4].G_{Enc} + resp_{C_{BP}}[1].H \stackrel{?}{=} T_{CT_v} + CT_v \cdot c$$
   (witnesses $r_3, v$ at indices [4], [1])
7. Verifies $CT_{at}$ using shared responses:
   $$resp_{C_{BP}}[5].G_{Enc} + resp_{AT}[0].H \stackrel{?}{=} T_{CT_{at}} + CT_{at} \cdot c$$
   (witness $r_4$ at index [5], $at$ from $resp_{AT}[0]$)

8. For each auditor encryption key $i$, verifies:
   - $Eph_{e_i}[0]$:
     $$resp_{C_{BP}}[2].E_i + resp_{Eph_{e_i}[0]}[1].(-B_{blinding}) \stackrel{?}{=} T_{Eph_{e_i}[0]} + Eph_{e_i}[0] \cdot c$$
     (witness $r_1$ at index [2], product $r_1 \cdot bl_i$ is second response)
   - Binding $l_i = bl_i$:
     $$resp_{C_{BP}}[14 + 2i].B \stackrel{?}{=} T_{bl_i} + (bl_i.B) \cdot c$$
     (reuses the $l_i$ response at index $[14 + 2i]$; $bl_i.B$ is the public second-generator blinding for leaf index $i+1$. This forces the $l_i$ used in $Eph_{e_i}[0]$ to equal the re-randomization blinding $bl_i$ of $E_i$.)
    - $Eph_{e_i}[1]$:
      $$resp_{Eph_{e_i}[1]}.Eph_{e_i}[0] \stackrel{?}{=} T_{Eph_{e_i}[1]} + Eph_{e_i}[1] \cdot c$$
     (witness $r_2/r_1$ at index [12] of $resp_{C_{BP}}$)
   - $Eph_{e_i}[2]$:
     $$resp_{Eph_{e_i}[2]}.Eph_{e_i}[0] \stackrel{?}{=} T_{Eph_{e_i}[2]} + Eph_{e_i}[2] \cdot c$$
     (witness $r_3/r_1$ at index [8] of $resp_{C_{BP}}$)
   - $Eph_{e_i}[3]$:
     $$resp_{Eph_{e_i}[3]}.Eph_{e_i}[0] \stackrel{?}{=} T_{Eph_{e_i}[3]} + Eph_{e_i}[3] \cdot c$$
     (witness $r_4/r_1$ at index [10] of $resp_{C_{BP}}$)

9. For each mediator $j$, verifies:
   - $CT_{m_j}$ (Partial2 commitment): Let $D_j = CT_{m_j} + J_0 + J_1 \cdot idx_j - M_j$, then:
     $$resp_{CT_{m_j}}[0].G_{Enc} + resp_{CT_{m_j}}[1].(-B_{blinding}) \stackrel{?}{=} T_{CT_{m_j}} + D_j \cdot c$$
   - Binding $bl_{n+j}$:
     $$resp_{CT_{m_j}}[1].B \stackrel{?}{=} T_{k_j} + (bl_{n+j}.B) \cdot c$$
     (reuses the $bl_{n+j}$ response from the $CT_{m_j}$ proof; $bl_{n+j}.B$ is the public second-generator blinding for leaf index $n+j+1$. This forces the $bl_{n+j}$ used in $D_j$ to equal the re-randomization blinding of $M_j$.)
    - $Eph_{m_j}$: Let base $= Eph_{e_{idx_j}}[0]$ (the auditor's $r_1$ ephemeral key from the leg encryption at the mediator's enc-key index), then using the $(m_j/r_1)$ response from $resp_{C_{BP}}$ at index $[14 + 2n + 2j + 1]$:
     $$resp_{C_{BP}}[14 + 2n + 2j + 1].base \stackrel{?}{=} T_{Eph_{m_j}} + Eph_{m_j} \cdot c$$

10. For each public encryption key $i$, verifies (using $r_1, r_2, r_3, r_4$ responses from $resp_{C_{BP}}$ at indices [2], [3], [4], [5]):
    - $Eph_{public\_e_i}[0]$: $$resp_{C_{BP}}[2].PK_i \stackrel{?}{=} T_{Eph_{public\_e_i}[0]} + Eph_{public\_e_i}[0] \cdot c$$
    - $Eph_{public\_e_i}[1]$: $$resp_{C_{BP}}[3].PK_i \stackrel{?}{=} T_{Eph_{public\_e_i}[1]} + Eph_{public\_e_i}[1] \cdot c$$
    - $Eph_{public\_e_i}[2]$: $$resp_{C_{BP}}[4].PK_i \stackrel{?}{=} T_{Eph_{public\_e_i}[2]} + Eph_{public\_e_i}[2] \cdot c$$
    - $Eph_{public\_e_i}[3]$: $$resp_{C_{BP}}[5].PK_i \stackrel{?}{=} T_{Eph_{public\_e_i}[3]} + Eph_{public\_e_i}[3] \cdot c$$

11. Verifies the Bulletproof commitment $C_{BP}$ using the response array $resp_{C_{BP}}$ and generators:
    $$resp_{C_{BP}}[0].B_{blinding} + resp_{C_{BP}}[1].G_1 + resp_{C_{BP}}[2].G_2 + ... \stackrel{?}{=} T_{C_{BP}} + C_{BP} \cdot c$$
    where the generators $G_i$ correspond to the witness array structure from the prover step 9. This verifies the Schnorr protocol for the Bulletproof commitment.

12. Verifier finally checks the Bulletproofs R1CS proof validates all arithmetic constraints (curve point validity, randomization consistency, curve tree membership, multiplication relations, and range proof).


## Mediator affirmation proof

A mediator for an asset can either accept or reject a leg in a settlement. The proof shows that the actor really is the mediator at index $j$ for this leg — i.e. that they hold both:

- $enc\_sk$ — the encryption secret key whose public key $EK_{idx_j}$ is the auditor encryption key at index $idx_j$ in the asset leaf (and which the leg encryption uses for $Eph_{m_j} = EK_{idx_j} \cdot r_{m_j}$), and
- $m\_sk$ — the mediator's affirmation secret key whose public key $MK = m\_sk.G_{Aff}$ is the affirmation key encrypted in this leg's $CT_{m_j} = r_{m_j}.G_{Enc} + MK$.

The proof is a single 2-witness Pedersen relation. Observe that the mediator can rewrite $CT_{m_j}$ using their two secrets:
$$CT_{m_j} = r_{m_j}.G_{Enc} + m\_sk.G_{Aff} = enc\_sk^{-1}.Eph_{m_j} + m\_sk.G_{Aff}$$
since $enc\_sk^{-1}.Eph_{m_j} = enc\_sk^{-1}.(EK_{idx_j}.r_{m_j}) = enc\_sk^{-1}.(enc\_sk.G_{Enc}.r_{m_j}) = r_{m_j}.G_{Enc}$. So proving knowledge of $(enc\_sk^{-1}, m\_sk)$ in
$$CT_{m_j} = enc\_sk^{-1}.Eph_{m_j} + m\_sk.G_{Aff}$$
simultaneously demonstrates that the actor holds both the right encryption secret key (for $idx_j$) and the affirmation secret key (for the $MK$ encrypted in $CT_{m_j}$). There is no separate decryption of $CT_{at}$ — the binding to the right mediator slot comes entirely from $Eph_{m_j}$ and $CT_{m_j}$ being public parts of the leg encryption at index $j$.

**Instance**: $CT_{m_j}, Eph_{m_j}, accept/reject, G_{Enc}, G_{Aff}, j, Leg\_Enc$

**Witness**: $enc\_sk, m\_sk$ (the prover supplies the raw $enc\_sk$; the inversion to $enc\_sk^{-1}$ happens inside the proof)

Above are the high level instance and witness values known before the protocol starts and don't include instance and witness created during protocol execution like blindings and $T$ values.

### Prover

1. Mediator indicates its acceptance or rejection of the leg and this is revealed to the chain and added to transcript.
2. Prover picks random blindings $enc\_sk^{-1}_r, m\_sk_r \in \mathbb{Z}_p$ and computes:
   $$T_{med} = enc\_sk^{-1}_r.Eph_{m_j} + m\_sk_r.G_{Aff}, \in \mathbb{G}_p$$
3. Prover hashes the following to create challenge $c$ as:
   $$c = Hash(accept/reject, Eph_{m_j}, G_{Aff}, CT_{m_j}, T_{med}, Leg\_Enc, nonce)$$
   where $Leg\_Enc$ is the full leg encryption (so the proof is bound to the specific leg) and $nonce$ is the usual application-level context.
4. Prover creates responses:
   $$resp_{enc\_inv} = enc\_sk^{-1}_r + enc\_sk^{-1}.c$$
   $$resp_{m\_sk} = m\_sk_r + m\_sk.c$$
5. The proof is
   $$(T_{med}, resp_{enc\_inv}, resp_{m\_sk})$$

### Verifier

1. Verifier checks that index $j$ corresponds to a mediator in the asset leaf and reads $Eph_{m_j}, CT_{m_j}$ for this mediator from the leg encryption.
2. Verifier adds the mediator's acceptance or rejection to the transcript.
3. Verifier reconstructs the challenge $c$ as:
   $$c = Hash(accept/reject, Eph_{m_j}, G_{Aff}, CT_{m_j}, T_{med}, Leg\_Enc, nonce)$$
4. Verifies the 2-witness Pedersen relation:
   $$resp_{enc\_inv}.Eph_{m_j} + resp_{m\_sk}.G_{Aff} \stackrel{?}{=} T_{med} + CT_{m_j}.c$$
   $$\implies (enc\_sk^{-1}_r + enc\_sk^{-1}.c).Eph_{m_j} + (m\_sk_r + m\_sk.c).G_{Aff} \stackrel{?}{=} enc\_sk^{-1}_r.Eph_{m_j} + m\_sk_r.G_{Aff} + CT_{m_j}.c$$
