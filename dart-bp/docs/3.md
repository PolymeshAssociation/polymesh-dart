# Asset Minting

This process is done by an issuer who wants to mint some quantity of an asset that he created into his own account. The asset-id is public and so is the minted amount. Issuer's key $AK$ and it identity $id$ are also public. The chain ensures that the total minted amount can never exceed $MAX\_BALANCE$ and thus there is no range proof required on the balance in the new state.

A successful completion of minting results in the following:

1. The issuer's old account state $State_{old}$ is invalidated and new state $State_{new}$ is created. However, $State_{old}$ cannot be revealed as it identifies which account state is being invalidated. So a randomized version of it $State_{old_r}$ is used in relations.
2. Nullifier $N=\rho_i.G_5$ is revealed by issuer and chain adds it to the nullifier set. Here $\rho_i$ refers to the nullifier secret key of $State_{old}$
3. The balance in $State_{new}$ is more than balance in $State_{old}$ by the minted amount
4. $State_{new}$ is inserted as a new leaf in the curve tree.

## Protocol

_The following description is for W1 (solo) where a single prover (the issuer) knows both secret keys $sk$ and $ek$ along with all other witnesses. The split-prover variant used in W2/W3 is described after the Verifier section below._

Here the prover (issuer) wants to prove following relations when minting amount $v$:

1. $State_{old} = sk.G_{Aff} + bal_0.G_1 + cnt.G_2 + at.G_3 + \rho.G_4 + \rho^i.G_5 + s.G_6 + s^i.G_7 + id.G_8 + ek.G_{Enc}$. Since the affirmation public key $AK$, encryption public key $EK$, asset-id $at$ and identity $id$ are public, the prover proves knowledge of the remaining values in the rerandomized state $State_{old_r} = State_{old} + b_0.H_0$, equivalent to proving $bal_0.G_1 + cnt.G_2 + \rho.G_4 + \rho^i.G_5 + s.G_6 + s^i.G_7 + b_0.H_0 = State_{old_r} - AK - EK - at.G_3 - id.G_8$
2. Similarly, $State_{new} = AK + bal_1.G_1 + cnt.G_2 + at.G_3 + \rho.G_4 + \rho^{i+1}.G_5 + s.G_6 + s^{i+1}.G_7 + id.G_8 + EK$. Since $bal_1 = bal_0 + v$, this is equivalent to $State_{new} - v.G_1 - AK - EK - at.G_3 - id.G_8 = bal_0.G_1 + cnt.G_2 + \rho.G_4 + \rho^{i+1}.G_5 + s.G_6 + s^{i+1}.G_7$
3. $State_{old}$ exists in the accumulator (account curve tree)
4. $N = \rho^i.G_5$
5. $AK = sk.G_{Aff}$
6. $EK = ek.G_{Enc}$
7. $\rho^{i+1} = \rho.\rho^i$
8. $s^{i+1} = s.s^i$
9. $bal_1 = bal_0 + v$

**Instance**: $State_{old_r}, State_{new}, AK, EK, at, N, id, v, Path_r, Root, G_{Aff}, G_{Enc}, G_i, H_i, \widetilde{G}, \widetilde{G}_i, \widetilde{H}, \widetilde{H}_i$

**Witness**: $sk, ek, bal_0, bal_1, cnt, \rho, \rho^i, \rho^{i+1}, s, s^i, s^{i+1}, b_0, Path$.

Above are the high level instance and witness values known before the protocol starts and don't include instance and witness created during protocol execution like the various blindings and $T$ values.

### Prover
1. Let $D_{old} = State_{old_r} - AK - EK - at.G_3 - id.G_8$ (everything subtracted is public to the verifier). Prover wants to prove knowledge of $bal_0, cnt, \rho, \rho^i, s, s^i, b_0$ in $bal_0.G_1 + cnt.G_2 + \rho.G_4 + \rho^i.G_5 + s.G_6 + s^i.G_7 + b_0.H_0 = D_{old}$
2. Similarly, let $D_{new} = State_{new} - v.G_1 - AK - EK - at.G_3 - id.G_8$. Prover wants to prove knowledge of $bal_0, cnt, \rho, \rho^{i+1}, s, s^{i+1}$ in $bal_0.G_1 + cnt.G_2 + \rho.G_4 + \rho^{i+1}.G_5 + s.G_6 + s^{i+1}.G_7 = D_{new}$.
3. Prover creates nullifier $N = \rho^i.G_5$
4. Prover gets the path of the leaf $State_{old}$ as $Path$, an array of nodes (curve points), and randomizes it, i.e all nodes in the path have a blinding added to them like $b_i*H_0$ or $b_i*\widetilde{H}_0$. This will result in the leaf $State_{old}$ being transformed into $State_{old_r} = State_{old} + b_0.H_0$ and $Path$ transforms into $Path_r$.
   Prover enforces the constraints for curve tree membership using $Path, Path_r, b_i$
5. Since prover knows the opening of $State_{old}$ and $b_0$, it can prove the knowledge of opening of $State_{old_r}$ as well. So relation 1 can be transformed as
   $$
   bal_0.G_1 + cnt.G_2 + \rho.G_4 + \rho^i.G_5 + s.G_6 + s^i.G_7 + b_0.H_0 = State_{old_r} - AK - EK - at.G_3 - id.G_8
   $$
   where the RHS is public. Now it starts proving the knowledge of these.
6. Prover picks random $sk_r, ek_r, cnt_r, bal_{0_r}, \rho_r, \rho_{i_r}, \rho_{{i+1}_r}, s_r, s^i_r, s^{i+1}_r, b_{0_{blinding}} \in \mathbb{Z}_p$ and creates:
   $$
   T_{State_{old_r}} = bal_{0_r}.G_1 + cnt_r.G_2 + \rho_r.G_4 + \rho_{i_r}.G_5 + s_r.G_6 + s^i_r.G_7 + b_{0_{blinding}}.H_0, \in \mathbb{G}_p
   $$
   
   $$
   T_{State_{new}} = bal_{0_r}.G_1 + cnt_r.G_2 + \rho_r.G_4 + \rho_{{i+1}_r}.G_5 + s_r.G_6 + s^{i+1}_r.G_7, \in \mathbb{G}_p
   $$

   Same blinding $bal_{0_r}$ is used for both old and new balance since the change in balance is public and can thus be used in verification check accordingly.
7. For the correctness of nullifier and knowledge of secret keys, prover creates
   $$T_{null} = \rho_{i_r}.G_5, \in \mathbb{G}_p$$
   $$T_{pk} = sk_r.G_{Aff}, \in \mathbb{G}_p$$
   $$T_{ek} = ek_r.G_{Enc}, \in \mathbb{G}_p$$
8. For enforcing, $\rho^{i+1} = \rho.\rho^i$, $s^{i+1} = s.s^i$, prover setups the constraints in Bulletproof as both of these are just multiplications. Prover uses Sigma protocol (Chaum Pedersen) to prove equality of committed values in Bulletproof's commitment (corresponding to its witnesses) and in $State_{old}, \text{and}, State_{new}$. Let $C_{BP_{\rho,s}}$ be the commitment to these values:
   $$C_{BP_{\rho,s}} = b'.H_0 + \rho.H_1 + \rho^i.H_2 + \rho^{i+1}.H_3 + s.H_4 + s^i.H_5 + s^{i+1}.H_6, \in \mathbb{G}_p$$
   Here $b'$ is the blinding to the commitment added by Bulletproof.
9. Prover proves knowledge of above committed values and equality of these with other commitments as:
   Pick random $r_{BP_{\rho,s}} \in \mathbb{Z}_p$ and create
   $$T_{BP_{\rho,s}} = r_{BP_{\rho,s}}.H_0 + \rho_r.H_1 + \rho_{i_r}.H_2 + \rho_{{i+1}_r}.H_3 + s_r.H_4 + s^i_r.H_5 + s^{i+1}_r.H_6, \in \mathbb{G}_p$$
10. Prover hashes the following to create challenge $c$ as:
    $$c = Hash(State_{old_r}, State_{new}, AK, EK, at, N, id, v, Path_r, Root, C_{BP_{\rho,s}}, T_{State_{old_r}}, T_{State_{new}}, T_{null}, T_{BP_{\rho,s}}, T_{pk}, T_{ek})$$
11. Prover now creates responses for sigma protocol for $resp_{state_{old_r}}$ =
    $$[\begin{matrix}
    bal_{0_r} + bal_0.c, & cnt_r + cnt.c, & \rho_r + \rho.c, & \rho_{i_r} + \rho_i.c, & s_r + s.c, & s^i_r + s^i.c, & b_{0_{blinding}} + b_0.c\\
    \end{matrix}]$$
12. Responses for sigma protocol for $resp_{state_{new}}$ =
    $$[\begin{matrix}
    \bot, & \bot, & \bot, & \rho_{{i+1}_r} + \rho_{i+1}.c, & \bot, & s^{i+1}_r + s^{i+1}.c\\
    \end{matrix}]$$
    
    The symbol $\bot$ indicates that no response is created for that witness since a response has been created for the same witness above. Because responses for $bal_0, cnt$, $\rho$, $s$ are already created in $resp_{state_{old_r}}$.
13. The response for nullifier secret key $\rho^i$ is already created in $resp_{state_{old_r}}$. Responses for witnesses $sk$ and $ek$ are
    $$resp_{pk} = sk_r + sk.c$$
    $$resp_{ek} = ek_r + ek.c$$
14. For relation $C_{BP_{\rho,s}}$, only the response for witnesses $b'$ needs to be created as the responses of other witnesses are already created in $resp_{state_{old_r}}$ and $resp_{state_{new}}$.
    $resp_{b'} = r_{BP_{\rho,s}} + b'.c$
15. The proof is
    $$(C_{BP_{\rho,s}}, State_{old_r}, State_{new}, Path_r, T_{State_{old_r}}, T_{State_{new}}, T_{null}, T_{BP_{\rho,s}}, T_{pk}, T_{ek}, resp_{state_{old_r}}, resp_{state_{new}}, resp_{pk}, resp_{ek}, resp_{b'})$$

### Verifier

1. Verifier hashes the following to create challenge $c$ as:
   $$c = Hash(State_{old_r}, State_{new}, AK, EK, at, N, id, v, Path_r, Root, C_{BP_{\rho,s}}, T_{State_{old_r}}, T_{State_{new}}, T_{null}, T_{BP_{\rho,s}}, T_{pk}, T_{ek})$$

2. Verifier enforces the Bulletproof constraints for the 2 multiplications: $\rho^{i+1} = \rho.\rho^i$ and $s^{i+1} = s.s^i$.

3. Verifier enforces the Bulletproof constraints for curve tree membership to verify that $Path_r$ leads to $Root$.

4. Verifies correctness of $State_{old_r}$ by checking:
   $$resp_{state_{old_r}}[0].G_1 + resp_{state_{old_r}}[1].G_2 + resp_{state_{old_r}}[2].G_4 + resp_{state_{old_r}}[3].G_5 + $$
   $$resp_{state_{old_r}}[4].G_6 + resp_{state_{old_r}}[5].G_7 + resp_{state_{old_r}}[6].H_0 \stackrel{?}{=} T_{State_{old_r}} + (State_{old_r} - AK - EK - at.G_3 - id.G_8).c$$

   $$\implies (bal_{0_r} + bal_0.c).G_1 + (cnt_r + cnt.c).G_2 + (\rho_r + \rho.c).G_4 + (\rho^i_r + \rho^i.c).G_5 + $$
   $$(s_r + s.c).G_6 + (s^i_r + s^i.c).G_7 + (b_{0_{blinding}} + b_0.c).H_0 \stackrel{?}{=} bal_{0_r}.G_1 + cnt_r.G_2 + \rho_r.G_4 + $$
   $$\rho^i_r.G_5 + s_r.G_6 + s^i_r.G_7 + b_{0_{blinding}}.H_0 + (State_{old_r} - AK - EK - at.G_3 - id.G_8).c$$

5. Verifies correctness of $State_{new}$ by checking:
   $$resp_{state_{old_r}}[0].G_1 + resp_{state_{old_r}}[1].G_2 + resp_{state_{old_r}}[2].G_4 + resp_{state_{new}}[3].G_5 + $$
   $$resp_{state_{old_r}}[4].G_6 + resp_{state_{new}}[5].G_7 \stackrel{?}{=} T_{State_{new}} + (State_{new} - v.G_1 - AK - EK - at.G_3 - id.G_8).c$$
   $$\implies (bal_{0_r} + bal_0.c).G_1 + (cnt_r + cnt.c).G_2 + (\rho_r + \rho.c).G_4 + (\rho^{i+1}_r + \rho^{i+1}.c).G_5 + (s_r + $$
   $$s.c).G_6 + (s^{i+1}_r + s^{i+1}.c).G_7 \stackrel{?}{=} bal_{0_r}.G_1 + cnt_r.G_2 + \rho_r.G_4 + \rho^{i+1}_r.G_5 + s_r.G_6 + s^{i+1}_r.G_7 + (State_{new} - v.G_1 - AK - EK - at.G_3 - id.G_8).c$$

   Note that for the $bal_0, cnt, \rho, s$ witnesses, verifier reuses responses from $resp_{state_{old_r}}$.

6. Verifies correctness of nullifier by checking:
   $$resp_{state_{old_r}}[3].G_5 \stackrel{?}{=} T_{null} + N.c$$
   $$\implies (\rho^i_r + \rho^i.c).G_5 \stackrel{?}{=} \rho^i_r.G_5 + N.c$$

7. Verifies knowledge of affirmation secret key by checking:
   $$resp_{pk}.G_{Aff} \stackrel{?}{=} T_{pk} + AK.c$$
   $$\implies (sk_r + sk.c).G_{Aff} \stackrel{?}{=} sk_r.G_{Aff} + AK.c$$

8. Verifies knowledge of encryption secret key by checking:
   $$resp_{ek}.G_{Enc} \stackrel{?}{=} T_{ek} + EK.c$$
   $$\implies (ek_r + ek.c).G_{Enc} \stackrel{?}{=} ek_r.G_{Enc} + EK.c$$

9. Verifier checks response for $C_{BP_{\rho,s}}$ as:
   $$resp_{b'}.H_0 + resp_{state_{old_r}}[2].H_1 + resp_{state_{old_r}}[3].H_2 + resp_{state_{new}}[3].H_3 + $$
   $$resp_{state_{old_r}}[4].H_4 + resp_{state_{old_r}}[5].H_5 + resp_{state_{new}}[5].H_6 \stackrel{?}{=} T_{BP_{\rho,s}} + C_{BP_{\rho,s}}.c$$
   $$\implies (r_{BP_{\rho,s}} + b'.c).H_0 + (\rho_r + \rho.c).H_1 + (\rho^i_r + \rho^i.c).H_2 + (\rho^{i+1}_r + \rho^{i+1}.c).H_3 + $$
   $$(s_r + s.c).H_4 + (s^i_r + s^i.c).H_5 + (s^{i+1}_r + s^{i+1}.c).H_6 \stackrel{?}{=} r_{BP_{\rho,s}}.H_0 + \rho_r.H_1 + \rho^i_r.H_2 + $$
   $$\rho^{i+1}_r.H_3 + s_r.H_4 + s^i_r.H_5 + s^{i+1}_r.H_6 + C_{BP_{\rho,s}}.c$$

10. Verifier finally checks the Bulletproofs proof for all constraints i.e. curve tree membership and multiplications


## Split prover variant (W2/W3)

In W2/W3 the work is split between a host (which does not know $sk, ek$) and a device (which holds $sk, ek$). The split is natural: the W1 protocol above already factors cleanly into

- a "state-and-nullifier" part — everything to do with $T_{State_{old_r}}, T_{State_{new}}, T_{null}, T_{BP_{\rho,s}}$, the curve tree membership for $Path_r$, and the corresponding responses $resp_{state_{old_r}}, resp_{state_{new}}, resp_{b'}$ — which involves only $bal_0, cnt, \rho, \rho^i, \rho^{i+1}, s, s^i, s^{i+1}, b_0$ as witnesses, and
- a "secret-key knowledge" part — $T_{pk}, T_{ek}$ and their responses $resp_{pk}, resp_{ek}$ — which involves only $sk, ek$.

The host runs the first part; the device runs the second part as a standalone Sigma proof of knowledge of $sk$ in $AK = sk.G_{Aff}$ and $ek$ in $EK = ek.G_{Enc}$, with both relations sharing the same challenge (single transcript). When the host runs alone, it drops $T_{pk}, T_{ek}$ from its $T$ values and from its challenge hash, and drops $resp_{pk}, resp_{ek}$ from its responses. Creation of $T_{State_{old_r}}, T_{State_{new}}, T_{null}, T_{BP_{\rho,s}}$ and the corresponding responses, the curve tree membership constraints, and the shared blindings between $State_{old_r}$ and $State_{new}$ all stay the same as in the W1 Prover above.

**Instance**: $AK, EK, G_{Aff}, G_{Enc}$

**Witness**: $sk, ek$

### Device prover
1. Pick random $sk_r, ek_r \in \mathbb{Z}_p$ and compute
   $$T_{pk} = sk_r.G_{Aff}, \quad T_{ek} = ek_r.G_{Enc}$$
2. Hash the device's transcript to get a challenge
   $$c = Hash(nonce, AK, EK, T_{pk}, T_{ek})$$
3. Responses
   $$s_{sk} = sk_r + sk.c, \quad s_{ek} = ek_r + ek.c$$

The device sends $(T_{pk}, T_{ek}, s_{sk}, s_{ek})$ to the verifier (or, in W3, to the host first).

### Device verifier
1. Recompute the challenge:
   $$c = Hash(nonce, AK, EK, T_{pk}, T_{ek})$$
2. Verify the affirmation key relation:
   $$s_{sk}.G_{Aff} \stackrel{?}{=} T_{pk} + AK.c$$
   $$\implies (sk_r + sk.c).G_{Aff} \stackrel{?}{=} sk_r.G_{Aff} + AK.c$$
3. Verify the encryption key relation:
   $$s_{ek}.G_{Enc} \stackrel{?}{=} T_{ek} + EK.c$$
   $$\implies (ek_r + ek.c).G_{Enc} \stackrel{?}{=} ek_r.G_{Enc} + EK.c$$

### Binding host and device

**W2 (parallel).** The device's $nonce$ is the same $nonce$ the host uses, so both proofs end up bound to the same context. The two proofs are produced independently and verified independently; nothing flows from one prover to the other during proving.

**W3 (sequential).** The host first runs its pre-challenge phase of the Prover above — picking all blindings and computing all $T$ values on the host side, but dropping the parts that involve $sk$ or $ek$ (so $T_{pk}$ and $T_{ek}$ are not computed and not added to its transcript). It then derives its challenge from that transcript exactly as the W1 challenge $c$ is derived but with $T_{pk}, T_{ek}$ omitted from the hash; call this challenge $c_H$. The host sends $c_H$ to the device. The device sets its $nonce$ to
$$nonce' = c_H \| nonce$$
(concatenation of the byte serialization of $c_H$ and the original $nonce$), runs the Device prover above against $nonce'$ — so its challenge becomes
$$c = Hash(nonce', AK, EK, T_{pk}, T_{ek}) = Hash((c_H \| nonce), AK, EK, T_{pk}, T_{ek})$$
— and sends $(T_{pk}, T_{ek}, s_{sk}, s_{ek})$ back to the host. The host appends the device proof bytes to its transcript and derives a fresh challenge
$$c_H' = Hash(c_H, T_{pk}, T_{ek}, s_{sk}, s_{ek})$$
which it uses for its own response generation. The verifier mirrors the same ordering: derives $c_H$, reconstructs $nonce' = c_H \| nonce$, verifies the device proof against $nonce'$, then derives $c_H'$ from the device proof bytes and verifies the host's responses against $c_H'$.
